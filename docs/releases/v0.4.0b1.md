# Saved to Shipped v0.4.0b1

The first free local beta turns a LinkedIn saved archive into a workspace for building, learning and revisiting useful ideas. It runs on your own computer with Python 3.10+, no third-party runtime dependencies and no application account or subscription.

This file is the release-note source. A GitHub release, tag or package-index publication exists only after the coordinator verifies and publishes that destination. The hosted application is not publicly deployed by this release.

## Start locally

Download the wheel attached to the GitHub prerelease, then install it in your Python environment:

```sh
python -m pip install ./saved_to_shipped-0.4.0b1-py3-none-any.whl
saved-to-shipped
```

The app opens on loopback. The synthetic demo works without provider keys and stays separate from personal data. A checkout also runs with `python3 server.py`; see the [usage guide](../USAGE.md) for installation, private paths, imports and exports.

No PyPI installation command is advertised until the project name, publishing identity and actual uploaded package have been verified.

## In this beta

- Import official LinkedIn Saved Items ZIP/CSV files without losing notes, grouping or progress when the archive is imported again.
- Keep a project board, a learning library and an experience library with distinct sections and reading progress.
- Return through Today, continue a useful read or build step, or find a forgotten idea across all spaces.
- Create sections in the organizing dropdown, retain empty sections and save the weekly time preference.
- Keep personal notes separate from source text, export a v1 backup and resume after restarting the app.
- Use system/light/dark appearance, narrow layouts and keyboard/touch controls with a consistent Saved to Shipped identity and clearer visual hierarchy.
- Keep unsaved notes and source edits until explicit discard, recover from a failed save, and return keyboard focus to the invoking control. Delayed manual polls cannot overwrite a newer notes editor.

Retrieval is optional and sends only explicitly selected URLs to the configured provider. The local path now enforces the same selected-ID boundary and charge approval as the shared form, rejecting invalid or changed selections before submission. AI organization is optional and uses the supplied context. Both use each user's own provider account and may incur its fees. Importing or saving keys never starts a request. Manual text, local rules, notes, reading and exports work without those services.

## Scope and limitations

LinkedIn's archive supplies saved URLs and dates, not the original authors' post text. Inaccessible, deleted, gated, partial or truncated content stays labeled. This release does not promise complete attachments or reliable recovery of every post. Native Reddit/Instagram import, reminders, a capped/ordered Read next shortlist and completed-session summaries remain future work.

The repository includes an optional Firebase/Cloudflare hosted implementation with Google and verified Email/password plus authenticator TOTP, private Firestore data and encrypted provider credentials. Its manifest remains disabled with zero admitted seats. This release does not certify a public hosted cohort, cloud physical-storage envelope or included API usage. Follow [hosted setup](../FIREBASE_SETUP.md) and [shipping gates](../SHIP_PLAN.md) before deployment or admission.

## Compatibility and recovery

Version-1 workspace backups remain supported. Source text, annotations, classification edits, typed sections and independent reading progress are preserved. Provider credentials stay outside exported workspaces.

Before changing versions, export a backup and stop the old local server. Keep the exported backup private. To roll back, install the last reviewed wheel in a separate environment, use a copy of the previous state or exported v1 backup, and verify it before replacing the active state. Never run two versions writing the same state concurrently. A previous wheel is a code rollback, not an automatic data restore.

Hosted rollbacks require Firestore-compatible code and the original server credential/encryption key custody. Do not point an old SQL-only build at a Firestore workspace or erase retained incompatible lifecycle state. Hosted rollout and restoration remain separate operator actions.
