## Implemented contract

The internal `Workspace.invoke` boundary verifies UID, generation and lifecycle on every operation. It has no public request route. Separate SQL tables store control state, metadata, bodies, groups, settings, imports, jobs, encrypted credential records and bounded receipts. There is no full-text index.

Metadata pages contain previews and revisions; opening an item loads its body. Revisions reject stale edits. Repeated imports preserve annotations, classifications and provider provenance. Source identity uses the existing canonical URL and 12-hex item ID inside the verified workspace. Version-1 exports and restores retain source text, notes, reading progress and organisation, but exclude credentials and internal job control state.

Limits are 1,000 saves, 5,000,000 logical UTF-8 bytes, 131,072 serialized UTF-8 bytes per item, 100 sections, 25 saves per mutation and 50 per metadata page. The hosted per-item bound makes every accepted item fit a restore request. Oversized updates fail atomically without truncating text. Receipts, imports, job history, group descriptions and settings have separate bounds. Provider jobs reserve logical space before processing and retain durable completion state.

Logical accounting counts canonical item JSON once plus persisted operational JSON. SQL metadata duplication and indexes are covered only by a provisional 7,000,000-byte used-page check. This is not evidence that allocated database storage remains below 8,000,000 bytes.

The implementation and a separate reviewer run passed all **14 workspace tests**. The reviewer built fresh modules into a disposable directory. Coverage includes forged owner/generation, two-user isolation, concurrent revisions, Unicode byte accounting, count/used-page rollback, idempotent import chunks, group/reading parity, bounded receipts, reservations, duplicate completion, deleted/recreated saves, late provider results, close/restart and v1 round trips.

Regressions cover each case, including an accepted 121 KB Unicode item and rejected growth with preserved prior state.

No cloud resources, real identity accounts or paid providers were used. No deployed capacity claim follows from these tests.
