## Capacity and release limits

The [final-schema capacity record](P6-LOCAL-CAPACITY.md) shows 1,000 typical saves fit, while Unicode, richer text and long-note profiles reach byte limits earlier. Rejected writes preserve prior state, and full backups restore into fresh workspaces. Near-limit churn can still prevent some reinsertions into the original object. Local database allocation/WAL can exceed 8 MB, and closing a workspace does not immediately reclaim its allocated local file.

Consequently P1/P6 physical allocation, cumulative deleted-workspace reclamation, cloud meter/CPU/duration and whole-service recovery gates remain open. Firebase Spark is not yet configured for a real Google canary. Live provider fidelity, unavailable outcomes and actual charge checks were not performed in this implementation turn. No 500-member production capacity is claimed.

The [shipping plan](../SHIP_PLAN.md) separates the account-free local release from the restricted hosted preview and subsequent measured cohorts. The [operations runbook](../HOSTED_OPERATIONS.md) records exact configuration, key retention, frozen-deletion recovery and rollback requirements. No hosted deployment or rollback version exists yet.
