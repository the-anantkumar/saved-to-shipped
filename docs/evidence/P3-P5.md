## Implemented boundaries

- Google ID tokens use maintained `jose` verification and bounded, cached official signing certificates. A 15-minute HMAC workspace capability binds verified UID and membership generation. Firebase account deletion/disablement/revocation is checked on session renewal and before privileged operations. Ordinary access has a maximum 15-minute revocation window; app suspension acts at the workspace boundary.
- Atomic membership reservations count toward the cap before provisioning. Default cap is zero. A configured admission UID allowlist restricts a closed preview. Lifecycle epochs reject reordered suspend/resume operations. Workspace cleanup precedes seat release; tombstones reject old generations.
- APIs reject hostile origins and client ownership selectors, cap JSON at 256 KiB, return metadata pages and use item revisions. Settings are encrypted before storage. An HMAC receipt fingerprint permits exact retries without storing plaintext keys or reusing encryption nonces.
- AES-GCM binds credentials to UID, generation, provider and key version. Export/public job projections exclude credentials and private control records. Credential rotation primitives are tested; fleet-wide key retirement tooling is not implemented.
- A durable QUEUED record precedes an atomic STARTING transition and one paid submission. Losing its response produces UNCERTAIN, never an automatic submission retry. Known runs use bounded status/dataset reconciliation; resuming first verifies run status even when a dataset already exists. Classification responses persist before application, so application retries do not call OpenAI again.
- Every attempted user mutation consumes allowance, including failed/replayed requests. Completion reserves 2,000 modeled write units, holds 128 for intent/control and deducts `16 * selected saves + 48` before each application/poll claim. The separate 24-claim ceiling also applies. Explicit resume requires a fresh reservation. These are conservative application units, not certified Cloudflare meter values.
- Daily pools are 40,000 ingestion, 30,000 interactive, 20,000 completion and 10,000 cleanup units. Cleanup works for suspended/deleting members. Each deletion/credential-repair attempt is charged; final cleanup reserves work based on retained item/operational counts.
- Deletion atomically freezes workspace mutations and new submissions. STARTING/UNCERTAIN jobs require reconciliation first. Known runs and encrypted keys remain until abort succeeds. A revoked key leaves a frozen, retryable deletion with a narrowly scoped replacement-key path under fresh authentication. Late results cannot revive the workspace.
