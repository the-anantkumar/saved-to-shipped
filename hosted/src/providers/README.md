# Provider boundary

These modules perform one explicitly requested operation using the user's supplied key. They do not read deployment provider keys, persist workspace data, retry a paid submission, or call a provider when credentials are merely saved. The trusted job orchestrator must commit submission intent first and reconcile known run references afterward.

- `createApify(fetcher)` offers `start`, `poll`, `abort` and `page`. Start accepts at most 25 LinkedIn links and an explicit $0.01–$20 maximum charge. It passes `maxTotalChargeUsd`, `maxItems`, `restartOnError=false` and fixed actor options disabling discovery/media downloads. This is the provider's cost contract, separate from free application hosting. [Run Actor](https://docs.apify.com/api/v2/actors-runs-post)
- Dataset requests use 25 unfiltered rows and an absolute 5,000-record bound. `clean=true` can produce short non-final pages, so pagination explicitly keeps empty rows while excluding hidden fields. Missing results are finalized only after an actual final page. [Dataset pagination](https://docs.apify.com/api/v2/dataset-items-get)
- `retrievalCandidates` matches LinkedIn activity/source keys, ignores ambiguous and unrelated rows, and emits bounded `{id,patch,quality}` candidates. It never mutates the supplied items. Storage owns annotation preservation and same-job source upgrades. `missingCandidates` is only for end-of-dataset finalization.
- `classify` makes one Responses request with `store:false`, a strict JSON schema and no tools. It receives only selected context, goals and group names, preserves the selected model, and returns at most 20 complete validated records within 200,000 normalized UTF-8 bytes. Unknown, malformed, refused or incomplete responses remain potentially charged and cannot trigger automatic retry. [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)

Every network operation uses a fixed provider origin, bearer headers, forbidden redirects, timeout and streamed response-byte limit. Error messages never include upstream bodies, fetch exceptions or credentials. `ProviderFailure.uncertain` distinguishes ambiguous paid submissions from definitive input/auth failures; a malformed successful response is still potentially billable.

Credential encryption is in `../credentials/index.ts`. Its deployment keyring is `{active:"v1",keys:{v1:"<32-byte-base64url-key>"}}`, with at most four versions retained during rotation. AES-GCM authenticates owner UID, membership generation, provider and key version. Decryption, tampering and missing-key failures are redacted. Keys and cleartext never belong in public API responses or exports.

The synthetic `tests/providers-app.test.mjs` and `tests/credentials.test.mjs` checks use injected fetch and local cryptography only. They establish protocol/validation behavior, not live retrieval fidelity, an actual provider charge, deployed CPU cost or storage capacity.
